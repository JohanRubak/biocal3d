# DINOv3 and Concerto feature pseudo masks

This adds `make_feature_pseudomasks.py` to the existing stage-ablation folder. It
uses the **local features before mean/max pooling**, not the stage-classifier
heatmaps. No encoder is retrained. It reads existing feature caches and produces
PCA colour maps, feature clusters, continuous pseudo scores, and candidate masks.

## What the scores mean

The default has no manual masks:

1. Fit PCA and feature clusters on training specimens, pooling data from all scanners.
2. Measure each cluster's frequency in baseline, partial and clean scans.
3. Give clusters enriched in baseline/partial relative to clean a higher score.
4. Apply this frozen mapping to the held-out development fold.

The cluster frequencies are averaged equally across scans within each scanner/stage,
then equally between baseline/partial, then equally across scanners. There is a
small neutral prior. Inspect `cluster_stage_association.csv` to see scanner differences.
Stage labels orient clusters; the code **does not label every baseline patch plaque**.

These are **stage-associated candidate regions**, not confirmed plaque. Cleaning
artifacts, substrate changes, growth cohort, rim shape or scanner effects can also
produce stage-associated features. A high score is not a calibrated probability
of plaque. A low score is not proof of plaque absence. Neutral clusters may remain
entirely uncertain; the script does not force a fixed plaque area on every specimen.

The optional seed mode below fits a separate local classifier using trusted or
weak spatial labels. This is also distinct from explaining the existing stage head.

## Install the update

Extract the updated ZIP to a temporary folder. Copy these new files beside your
existing `stage_ablation.py`:

- `make_feature_pseudomasks.py`
- `PSEUDO_MASKS.md`
- `test_feature_pseudomasks.py` (optional checks)

Your existing run, checkpoints, stage heads and encoder settings can stay as they
are. The ZIP includes the original stage-ablation modules for a complete package;
you only need the new files above in your existing working folder.

## 1. Ensure local features are cached

Run from your existing stage-ablation folder. Replace `runs/stage_pooled_v3` with
your actual existing run directory throughout. **Do not run `prepare` again.**

If you already extracted **development** features using `--spatial`, skip this step.
Making test heatmaps only establishes that test spatial features exist; the new
workflow also needs development spatial features for fitting.

Repeat your original extraction commands with `--spatial`. With the original
default settings and checkpoint locations these are:

```bat
conda run --no-capture-output -n biocal3d-dinov3 python stage_ablation.py extract --run runs/stage_pooled_v3 --encoder dinov3 --repo vendor/dinov3 --checkpoint weights/dinov3_vits16_pretrain_lvd1689m-08c60483.pth --partition development --spatial
conda run --no-capture-output -n biocal3d-concerto python stage_ablation.py extract --run runs/stage_pooled_v3 --encoder concerto --repo vendor/concerto --checkpoint weights/concerto_small.pth --partition development --spatial
```

If you originally changed image size, field of view, point count, voxel size,
attention patch size, checkpoint path, device or repository, repeat those same
arguments. The extraction code checks provenance and rejects mismatched settings.
On WSL, use the same `--snapshot` path mapping as your original extraction.
The cached vectors are recomputed only when their local features are missing.
Saving local features can require several GB; the compressed caches contain all
patch/point channels, not just the pooled scan vectors.

Concerto prediction previews also need the corresponding original DINO render
folders, generated by the DINO extraction above. Both pseudo-models can subsequently
run from the DINO Python environment using cached data, without loading a GPU model.

## 2. Fit feature models on development training folds

```bat
conda run --no-capture-output -n biocal3d-dinov3 python make_feature_pseudomasks.py fit --run runs/stage_pooled_v3 --model-dir runs/stage_pooled_v3/pseudo_models_v1
```

Defaults: RGB DINOv3 and RGB Concerto, eight feature clusters, 32 PCA components,
up to 256 sampled feature vectors per scan for PCA/clustering, seed 123. All valid
local features in each training scan contribute to cluster-stage frequencies.
There is one feature model per input condition, shared across scanners.

**Development fold 0 is reserved for assessment**, so a default complete cohort
uses 24 specimens for fitting and 12 for validation. The original 12 test specimens
are not loaded for fitting. This preserves the original specimen grouping and
keeps scanner views/stages of a physical specimen together. These development
specimens may have been used for earlier stage-model development; this is an
internal held-out check for the newly fitted pseudo-model, not new independent data.

Use `--validation-fold 1` or `2` for a separate fit in a new model directory if
needed. Existing model/output directories are never overwritten. The script
records cohort/config/cache fingerprints and rejects mismatched inputs.

To include all four input conditions:

```bat
conda run --no-capture-output -n biocal3d-dinov3 python make_feature_pseudomasks.py fit --run runs/stage_pooled_v3 --model-dir runs/stage_pooled_v3/pseudo_models_all_v1 --modes dinov3_rgb dinov3_gray concerto_geometry concerto_rgb
```

## 3. Make a first preview from all scanners and stages

```bat
conda run --no-capture-output -n biocal3d-dinov3 python make_feature_pseudomasks.py predict --run runs/stage_pooled_v3 --model-dir runs/stage_pooled_v3/pseudo_models_v1 --out runs/stage_pooled_v3/pseudo_preview_v1 --limit 12
```

This selects scans round-robin across available scanner/stage groups. Each
comparison has a row per model and five columns:

1. Original RGB scan.
2. Local features in PCA colours, using one training-fitted colour scale per model.
3. Feature clusters. Cluster IDs/colours are arbitrary, with fixed IDs within a model.
4. Nonclean-stage association score (or a weak-seed classifier score).
5. Candidate mask overlay: gold plaque-like, blue uncertain, unmarked clean-like.

PCA colours are comparable between scans within one fitted model, not between
DINOv3 and Concerto or between independently fitted models. PCA colours alone
do not define a plaque class. DINO grayscale/Concerto geometry rows show the original
RGB for anatomical reference; RGB was not added to their cached feature inputs.

Remove `--limit 12` and choose a new `--out` for all validation scans. Select
specific scans with `--scan SCAN_ID ...` or scanners with `--scanner TRIOS5 iTERO`.

Default score thresholds are <=0.35 clean-like and >=0.65 plaque-like; the middle
remains uncertain. They are exploratory defaults, not validated operating points.
Inspect validation results before choosing settings. To change them, use e.g.
`--low 0.3 --high 0.7` and a new output directory. Do not choose thresholds to
maximize apparent performance on the locked test set.

## Output files

- `summary.csv`: native plaque-like/uncertain/clean-like fractions and mean pseudo
  scores, grouped by scan and mode. These are not validated plaque-coverage estimates.
- `<scan>/comparison.png`: all requested models side by side.
- `<scan>/<mode>/pseudo_mask.png`: **0=clean-like, 128=uncertain, 255=plaque-like**.
  Background/uncovered pixels are also 128; use `valid_mask.png` and `covered_mask.png`
  to distinguish them. This avoids marking missing predictions as clean.
- `pca.png`, `original.png`: full-size view and feature colours.
- `native_features_map.npz`: scores, clusters, pseudo labels, PCA colours,
  provenance, threshold settings and coordinate correspondence. Native label -1
  means uncertain, 0 clean-like, 1 plaque-like. For DINO, `eligible` identifies
  flattened grid cells represented by those arrays; `shape` reconstructs the grid.
- Concerto also writes `pseudo_points.ply` with native XYZ, pseudo-mask RGB, pseudo score,
  pseudo label and cluster ID; these are the original sampled surface positions.
  Point colours are gold=plaque-like, blue=uncertain, grey=clean-like.

DINO uses native patch resolution: 448-pixel images give a 28x28 patch grid.
Increasing display size does not create finer segmentation. Cells with less than
50% ROI coverage are excluded by default, leaving some boundary pixels uncovered.
Concerto's native point features may repeat across voxel/hierarchy groups.
Its 2D preview uses the nearest projected XY point within 0.35 mm; it is a flat
surface approximation that can mix layers on overhanging geometry. Native NPZ/PLY
files preserve the full 3D positions for inspection. No smoothing is used to make
the candidate masks look more precise than their source features.

Fractions use ROI-covered patch weights for DINO and area-sampled point counts
for Concerto, rather than triangle counts or raw mesh vertex counts. DINO fractions
refer to represented projected area and Concerto fractions approximate sampled
surface area. They should not be assumed numerically identical quantities.

## Optional: fit using plaque/clean seed regions

This is useful when conservative GMM/boosting regions or trusted manual seeds
are available. Supply spatial labels **only from the training folds**. Validation
and test scan IDs are rejected. A colour-mask-derived seed model can inherit its
teacher's errors; agreement with those same seeds is not independent validation.

Create a CSV with columns `scan_id,mode,path`. Paths are relative to the CSV or
absolute. Include one row per scan/mode that has seeds. Each mode using seeds
needs both classes across its supplied scans.

For DINO, provide a PNG matching `rgb.png` exactly: 0=trusted clean, 128=ignore,
255=trusted plaque. Use broad ignore regions; a conventional binary GMM PNG would
otherwise declare every black pixel trusted clean. Only patches whose ROI area
is at least 90% one seed class are labelled. Background is excluded.

For Concerto, provide an NPZ containing `labels` (-1 ignore, 0 clean, 1 plaque)
in the exact original cached point order, and `xyz_mm` matching those points.
The script checks coordinates before accepting labels. Obtain coordinate order
from the corresponding spatial cache and preserve it while assigning labels.

```csv
scan_id,mode,path
YOUR_TRAIN_SCAN_ID,dinov3_rgb,seeds/conservative_seeds.png
YOUR_TRAIN_SCAN_ID,concerto_rgb,seeds/conservative_point_seeds.npz
```

```bat
conda run --no-capture-output -n biocal3d-dinov3 python make_feature_pseudomasks.py fit --run runs/stage_pooled_v3 --model-dir runs/stage_pooled_v3/pseudo_seeded_v1 --seeds-csv seeds.csv
```

PCA/clustering still use all training scans; a small regularized logistic-regression
head then fits the selected local seed features. Its scores replace stage-association
scores for that mode. They are not calibrated probabilities because the seeds
are selectively sampled and classes are balanced during fitting. Modes without
seed rows continue to use stage association.

## Test previews after settings are settled

If needed, repeat the original extraction commands with `--partition test --spatial`.
Then explicitly request test output:

```bat
conda run --no-capture-output -n biocal3d-dinov3 python make_feature_pseudomasks.py predict --run runs/stage_pooled_v3 --model-dir runs/stage_pooled_v3/pseudo_models_v1 --partition test --out runs/stage_pooled_v3/pseudo_test_v1
```

This uses the same training-fitted model without fitting on test features or labels.
The script does not calculate Dice/IoU: those require independent spatial reference
labels. Stage accuracy, attractive pictures and agreement with a GMM teacher do
not establish segmentation accuracy. No real BioCal3D scans or weights were
available during implementation; synthetic tests verify mechanics, not biological
validity or actual GPU extraction.

## Checks

```bat
conda run --no-capture-output -n biocal3d-dinov3 python -m unittest test_feature_pseudomasks -v
```

Checks cover both modalities/all four scanners, specimen isolation, stale caches,
validation-seed rejection, explicit uncertainty, the optional seed classifier and
image/point-cloud exports. They create temporary synthetic data only.
